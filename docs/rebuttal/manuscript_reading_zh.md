# MASRubric：按改写稿理解方法与实验

## 先用一个例子理解

某个数学 agent 把一个几何问题中的外角当成内角，后面的 agent 直接引用这个结论，最后整条推理都错了。MASRubric 在这条消息被传播之前，检索出“角的类型是否认错”“弧长是否使用了正确的圆心角”等检查项，让审计模型逐项检查。通过就发送；未通过就把具体诊断交给原 agent 重写；重写到上限仍未通过就扣住这条消息。

改写稿把核心问题放在“测试时拿什么标准审计一条新消息”：提前从失败经历中提炼通用检查项，再按当前消息选出适用的检查项。离线构造的检查项库、在线检索和审计后的干预共同构成方法。

## 改写改变了阅读重点

| 旧 AgentDropoutV2 表述 | MASRubric 改写稿的重点 | 实验要回答的问题 |
| --- | --- | --- |
| Rectify-or-reject pruning，先纠错再拒绝 | 使用失败蒸馏的 pitfall rubrics 审计信息流 | 检查项本身带来了多少收益？ |
| Adversarial indicator pool | 可复用的 rubric criterion bank | 为什么这些检查项能适用于新的消息？ |
| Retrieval-augmented rectifier | 根据适用条件选择 context-specific rubric | 选出的检查项是否真的与当前推理情境相关？ |
| Correct / prune | Pass / Revise / Withhold | 诊断、重写和阻止传播分别产生什么作用？ |
| 各难度上的重试、拒绝统计 | 检查项使用随任务变化，审计投入随难度变化 | 这些统计能否稳定反映难度，是否与正确性有关？ |
| 跨框架、跨模型 | 同一个 8B 失败库直接用于 14B | 库的适用性、推理模型能力和审计模型能力各自贡献多少？ |

一条 criterion 是一个检查项；针对一条消息选出的多条 criterion 合起来才是 rubric。代码中的 `metric`、`indicator`、`pool` 是历史命名，对应关系见[运行说明](../paper_main_reproduction.md#criterion-bank-terminology)。

## 数据和标签分别在哪里用

1. 离线收集：用训练集问题和已有标准答案运行 MAS。比较最终答案与标准答案，筛选失败轨迹。这里需要数据集已有的答案或测试用例。
2. 离线提炼：miner 读取失败轨迹、标准答案、agent 角色及其输出，生成检查项。每项包括名称、错误根因、适用条件、检查指令。去重模型再合并重复项，生成固定库。
3. 在线执行：输入新问题及当前 agent 消息，检索并检查适用项。此时标准答案不应进入 solver、selector、retrieval 或 auditor 的输入。
4. 最终评测：运行结束后，独立 grader 使用测试集答案或测试用例判分。这与第 3 步的在线推理分开。

因此，“不用人工标注”指无需人工逐条编写检查项或逐条标注中间消息。构库仍使用训练集已有的监督信号；最终准确率仍需要测试标签。数学用现成答案和数学判题器；代码用现成测试用例执行验证。执行检查项审计的是模型，审计 verdict 的质量需要单独评估。

## 最值得补强的证据

- 成对独立重复：为相同任务、相同种子计划同时运行 baseline 和 MASRubric，直接看增益及其不确定性。AIME 每套只有 30 题，一题就是 3.33 个百分点。
- 同等预算对照：在 token、调用数或 wall time 的共同上限下比较 MASRubric、Self-Refine、PRM、在线 rubric 生成。当前成本表提供观察到的成本，严格预算实验需要预先固定停止规则。
- 检索质量：用固定的一组中间消息评估检查项是否适用、能否发现真实错误，并对比随机项、通用项和在线生成项。benchmark 间 top-10 Jaccard 相似度衡量使用模式差异，直接检索精度还需要逐消息判断。
- 干预归因：保存重写前后答案、审计判断和下游完整轨迹，统计纠正、破坏和漏检；再做修正与 withholding 的拆分对照。
- 标签隔离与迁移：明确训练来源、测试来源、题目 ID 和去重规则；固定库跨 benchmark 和模型使用，并逐项记录变化的 reasoner、auditor、selector。
- 审计失败处理：把“判断为空”“解析失败”“API 异常”和真正的通过区分开，记录覆盖率和最终影响。

实验任务、历史证据使用方式和准备状态见[实验准备与证据清单](experiment_readiness_zh.md)。
